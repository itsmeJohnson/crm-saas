# Production Rollout Guide: Telecalling Agency CRM with Gupshup WhatsApp

This document outlines the step-by-step production rollout procedure for deploying the **Telecalling CRM** on a single Ubuntu VPS with **Docker Compose**, **Nginx TLS (Let's Encrypt)**, and the **Gupshup WhatsApp Enterprise Messaging API** integration.

---

## 1. System Architecture Overview

```
                          Internet / Customers / Gupshup Webhooks
                                            │
                                            ▼ HTTPS (443)
                         ┌──────────────────────────────────────┐
                         │       Nginx Reverse Proxy & SSL      │
                         │      (Let's Encrypt / Certbot)       │
                         └──────────────────┬───────────────────┘
                                            │
                     ┌──────────────────────┴──────────────────────┐
                     │                                             │
                     ▼ /api/v1/*, /ws, /uploads                    ▼ /*
        ┌─────────────────────────┐                  ┌─────────────────────────┐
        │   FastAPI CRM Backend   │                  │   React CRM Frontend    │
        │      (Port 8000)        │                  │      (Port 80/3000)     │
        └────────────┬────────────┘                  └─────────────────────────┘
                     │
       ┌─────────────┴─────────────┐
       ▼                           ▼
┌──────────────┐            ┌──────────────┐
│  PostgreSQL  │            │    Redis     │
│ Database 15  │            │ Cache & Jobs │
└──────────────┘            └──────────────┘
```

- **Host OS:** Ubuntu 22.04 LTS / 24.04 LTS (Recommended: 4 vCPU, 8 GB RAM, 80 GB SSD)
- **Container Runtime:** Docker 24+ & Docker Compose v2
- **WhatsApp Provider:** Gupshup Enterprise WhatsApp Messaging API (`api.gupshup.io`)
- **Credentials at Rest:** AES-256 encrypted using `TELEPHONY_ENCRYPTION_KEY`

## 2. Server Prerequisites & Docker Setup

On a fresh Ubuntu VPS:

```bash
# 1. Update OS packages
sudo apt update && sudo apt upgrade -y

# 2. Install essential tools and Docker
sudo apt install -y curl git ufw jq openssl certbot python3-certbot-nginx

# 3. Install Docker Engine and Compose v2
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER

# 4. Configure firewall (UFW)
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp    # SSH
sudo ufw allow 80/tcp    # HTTP (Certbot verification)
sudo ufw allow 443/tcp   # HTTPS
sudo ufw enable
```

## 3. Clone Repository & Configure Environment

```bash
# 1. Clone repository to /opt/apps/crm
sudo mkdir -p /opt/apps
sudo chown -R $USER:$USER /opt/apps
cd /opt/apps
git clone <YOUR_GIT_REPO_URL> crm
cd /opt/apps/crm

# 2. Create production .env file
cp .env.production.example .env
```

### Required `.env` Variables:

Generate strong random secrets for `JWT_SECRET_KEY` and `TELEPHONY_ENCRYPTION_KEY`:

```bash
# Generate JWT Secret (32 bytes hex)
openssl rand -hex 32

# Generate Telephony / WhatsApp AES-256 Key (32 bytes base64)
python3 -c "import os,base64;print(base64.b64encode(os.urandom(32)).decode())"

# Generate strong passwords for DB and Redis
openssl rand -hex 16
```

Populate `/opt/apps/crm/.env`:

```ini
ENVIRONMENT=production
PROJECT_NAME="Telecalling CRM"

# Domains & Origins
DOMAIN=crm.youragencydomain.com
FRONTEND_URL=https://crm.youragencydomain.com
BACKEND_CORS_ORIGINS=https://crm.youragencydomain.com

# Core Security Keys
JWT_SECRET_KEY=<YOUR_GENERATED_JWT_KEY>
TELEPHONY_ENCRYPTION_KEY=<YOUR_GENERATED_BASE64_AES_KEY>

# PostgreSQL Configuration
POSTGRES_SERVER=db
POSTGRES_USER=crm_admin
POSTGRES_PASSWORD=<STRONG_POSTGRES_PASSWORD>
POSTGRES_DB=crm

# Redis Configuration
REDIS_HOST=redis
REDIS_PORT=6379
REDIS_PASSWORD=<STRONG_REDIS_PASSWORD>

# Storage & Uploads
UPLOAD_DIR=/app/uploads
```

## 5. Nginx & Let's Encrypt SSL Setup

Create host Nginx configuration `/etc/nginx/sites-available/crm.conf`:

```nginx
server {
    listen 80;
    server_name crm.youragencydomain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name crm.youragencydomain.com;

    # SSL Certbot paths (will be generated by certbot)
    ssl_certificate /etc/letsencrypt/live/crm.youragencydomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/crm.youragencydomain.com/privkey.pem;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    client_max_body_size 50M;

    # Backend API & Gupshup Webhooks
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # WebSocket Real-Time Chat & Telecaller Notifications
    location /ws {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
    }

    # Uploaded media (attachments, audio, images)
    location /uploads/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
    }

    # Frontend Single Page Application
    location / {
        proxy_pass http://127.0.0.1:80;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

Enable site and request SSL certificate:
```bash
sudo ln -s /etc/nginx/sites-available/crm.conf /etc/nginx/sites-enabled/
sudo certbot --nginx -d crm.youragencydomain.com
sudo systemctl reload nginx
```

## 6. Gupshup WhatsApp Integration Configuration

### Step A: Locate Gupshup Credentials
1. Log in to [Gupshup Enterprise Messaging Console](https://enterprise.gupshup.io/) (or [Gupshup WhatsApp Dashboard](https://www.gupshup.io/whatsapp/dashboard)).
2. Select your approved **WhatsApp App**.
3. Copy:
   - **App Name** (e.g., `telecallagencywa`)
   - **API Key / Token** (under App Settings / Security)
   - **Sender WhatsApp Phone Number** (e.g., `919876543210` - include country code without `+`)

### Step B: Connect in Telecalling CRM
1. Open CRM Dashboard: `https://crm.youragencydomain.com`
2. Navigate to **Settings** → **WhatsApp Settings** (or **Settings** → **Marketplace** → **Gupshup**).
3. Click **Connect WhatsApp** → Select **Gupshup WhatsApp API**.
4. Enter:
   - **Channel Label:** e.g., `Primary Sales Line`
   - **Gupshup App Name:** `telecallagencywa`
   - **Gupshup API Key:** `<YOUR_API_KEY>`
   - **Sender Phone Number:** `919876543210`
5. Click **Connect Gupshup Channel**.
6. The CRM will encrypt the API key and display your **Webhook Callback URL**.

### Step C: Configure Callback URL in Gupshup Dashboard
1. Copy the Callback URL from the CRM:
   ```
   https://crm.youragencydomain.com/api/v1/whatsapp/webhook/gupshup
   ```
2. In the Gupshup Console for your app:
   - Navigate to **App Settings** → **Callback URL**.
   - Paste the Webhook Callback URL.
   - Under Events to Forward, check:
     - `Inbound Messages` (text, images, documents, audio notes)
     - `Message Events` (`enqueued`, `sent`, `delivered`, `read`, `failed`)
   - Save changes.

## 7. Telecalling Agency Operational Workflows

### 1. Inbound Lead Capture & Conversation Linking
- When a customer sends a WhatsApp message to the Gupshup phone number:
  - The webhook handler automatically checks if a **Lead** exists for that phone number.
  - If no Lead exists, it creates a new Lead with stage "New Lead" and source "WhatsApp".
  - It creates/updates the conversation thread in the WhatsApp Workspace and sounds an in-app alert.

### 2. Telecaller Assignment & Composer Lock
- **Lead Assignment:** Managers can assign conversation threads to specific telecallers, or telecallers can claim unassigned leads.
- **Composer Lease Lock:** When an agent starts composing a reply to a lead, a 5-minute lease lock prevents other telecallers from colliding or sending duplicate responses to the same customer.

### 3. WhatsApp 24-Hour Messaging Window
- Meta/Gupshup enforces a 24-hour customer service window for free-form replies after the customer's last inbound message.
- If outside the 24-hour window, the CRM composer prompts the telecaller to send an approved **WhatsApp HSM Template**.
- Synchronize templates anytime from the CRM using the **Refresh Metadata / Sync Templates** button.

## 8. Backup & Maintenance Automation

Set up automated daily database backups via cron:

```bash
# Open crontab
crontab -e

# Run daily backup at 2:30 AM
30 2 * * * /opt/apps/crm/ops/backup.sh >> /var/log/crm_backup.log 2>&1
```

To deploy future updates cleanly:
```bash
/opt/apps/crm/ops/deploy.sh
```
